# Соглашения

Правила, по которым устроены раны, реестр и журнал. Если что-то из этого
неудобно — меняйте правило здесь и приводите код в соответствие, а не
заводите исключение в отдельном ране.

## Роли файлов

| Файл | Кто пишет | Когда меняется |
|---|---|---|
| `EXPERIMENTS.md` | человек или агент | после каждого эксперимента, только дописывается |
| `RESULTS.md` | таблица — `report_phase0.py`, разбор — человек | `make report` |
| `runs/INDEX.md` | `runs_index.py` | `make report` |
| `runs/<id>/manifest.json` | `exp.py` | никогда руками |

Правило: всё, что генерируется, руками не правится. Если нужно поменять
сгенерированное — меняется генератор.

## run_id

```
<YYYY-MM-DD>-<slug>[-<tag>]
```

Дата — день запуска, слаг — из имени конфига (`qrag_steps6.yaml` →
`qrag-fixed-steps6`, если в конфиге задано поле `slug`, иначе
`qrag-steps6`). Лексикографический порядок каталогов совпадает с
хронологическим.

Повторный прогон той же конфигурации в тот же день требует `--tag`:
`--tag dedupe-off` даёт `2026-07-28-qrag-steps6-dedupe-off`. Без этого
`exp.py` откажется писать в существующий каталог — молча затирать результат
он не умеет по замыслу.

## Что лежит в каталоге рана

| Файл | В git | Что это |
|---|---|---|
| `manifest.json` | да | параметры, хеши кода и входов, стадии, окружение, метрики |
| `metrics.json` | да | EM, F1, judge, title-метрики |
| `cmd.sh` | да | точные команды стадий; пишется **до** запуска |
| `notes.md` | да | наблюдения по конкретному рану, необязательно |
| `log.txt` | нет | stdout и stderr всех стадий |
| `retrieval.jsonl` | нет | выход retrieve, десятки-сотни МБ |
| `answer_judge.json` | нет | выход reader + judge, до полугигабайта |

Разделение простое: **в git — реестр, на диске — нагрузка.** Реестр целиком
текстовый и мелкий, он и есть история экспериментов; JSONL и answer JSON
лежат рядом, но вне репозитория, и восстанавливаются повторным прогоном по
`cmd.sh`.

**Раны до 2026-08-11 зовут скрипты из корня репозитория** — `python
fullwiki_qrag.py retrieve …`, — потому что модули лежали там. С этой даты они
переехали в `src/`, и новые `cmd.sh` пишут `python src/fullwiki_qrag.py`.
Старые файлы не переписаны намеренно: `cmd.sh` — дословная запись того, что
было запущено, и подмена команды задним числом сделала бы её ложной. Чтобы
воспроизвести ран той эпохи, добавьте `src/` к имени скрипта; всё остальное в
команде осталось верным. Каталог рана и его имя не менялись, `exp.py` тоже
остался в корне, поэтому последняя строка `python exp.py run --only score`
работает во всех `cmd.sh` без правок.

Нужен новый мелкий артефакт в git — добавьте его имя негацией в
[.gitignore](../.gitignore). Запрет по умолчанию (`runs/**`) оставлен
намеренно: он защищает репозиторий от случайно закоммиченного
полугигабайтного файла.

## Манифест

Схема — `runlib.MANIFEST_SCHEMA_VERSION`. Ключевые поля:

- `status` — `ok`, `failed` или `running`. Упавший ран тоже сохраняется:
  «это уже пробовали и оно не работает» — полезное знание.
- `code.git_commit`, `code.git_dirty`, `code.scripts` — каким кодом получен
  ран. `git_dirty: true` означает, что коммит не описывает содержимое
  полностью, и результат воспроизводим только по `cmd.sh`.
- `inputs` — заполняется из манифеста индекса, поэтому sha256 корпуса,
  revision энкодера и идентичность чекпоинта попадают в ран без чтения 14 ГБ.
- `stages[]` — argv, код возврата, время, размер и sha256 выхода.
- `env` — версии интерпретатора и библиотек, GPU. Нужен, чтобы «на чём это
  считалось» не приходилось восстанавливать по дате рана.
- `backfilled: true` — параметры восстановлены из документации, а не
  записаны в момент запуска (раны до 2026-07-28). Метрики у них настоящие.

## Что делает результаты сопоставимыми

В одну таблицу сравнения попадают только раны с одинаковым числом примеров и
`status: ok`; остальные `runs_index.py` исключает с предупреждением. Кроме
этого числа за сопоставимость отвечает человек. Минимум, что нужно держать
одинаковым между сравниваемыми ранами:

- одна и та же выборка и её порядок,
- одни и те же reader и judge, `max_tokens` 1000 и 100,
- один и тот же режим (`fixed` против `refresh` не сравнивается),
- title deduplication включена и с одной и той же квотой
  (`--max-chunks-per-title`; умолчания разные: 1 у `retrieve`, 2 у `search` —
  см. [gotchas.md](gotchas.md)).

Почему именно это — [gotchas.md](gotchas.md).

## Запись в журнале

```markdown
## <дата> — <короткое утверждение, а не тема>

**Раны:** `<run_id>`, `<run_id>`

**Гипотеза:** что проверяли и чего ожидали.

**Итог: подтверждена / опровергнута / неоднозначно.** Числа, на которых это
видно, с указанием сравнения и значимости.

**Почему.** Механизм, а не пересказ таблицы: какая метрика объясняет
результат и через что.

**Что дальше.** Следующий шаг или чего делать не стоит.
```

Заголовок формулируется утверждением: «Q-RAG-реранкер проигрывает
first-stage на всех бюджетах», а не «Эксперименты с Q-RAG». По оглавлению
журнала должно быть видно, что уже известно, без чтения записей целиком.

## Конфиги

Один конфиг — одна конфигурация эксперимента, лежит в `configs/` и
версионируется. Поля:

- `label` — как строка называется в таблице сравнения; по нему же строятся
  пары для McNemar в `runs_index.DEFAULT_PAIRS`.
- `slug`, `order` — имя каталога рана и позиция строки в `RESULTS.md`.
- `hypothesis` — попадает в манифест и должна отвечать на «зачем этот ран».
- `dataset` — ключ из `runlib.DATASETS`; умолчание `hotpotqa_dev_fullwiki`.
  От него зависят потолок покрытия в `metrics.json` и то, в какую таблицу
  `RESULTS.md` попадёт строка, поэтому опечатка отбрасывается `exp.py` ещё до
  запуска: час GPU не должен тратиться на строку, которая уедет в чужую
  таблицу. Раны разных датасетов не сравниваются ни таблицей, ни МакНемаром.
- `retrieve.kind` — `qrag` (полный ретривал), `variant` (производная от
  другого рана: усечение, пустой контекст, oracle), `pool` (выбор из
  логированных кандидатов другого рана) или `search` (прямой итеративный
  поиск state-башней; без `checkpoint` — zero-shot стоковой GTE).
- `judge` — reader и judge; менять `max_tokens` можно только вместе с
  пересчётом всех сравниваемых строк.

Новый эксперимент начинается с копии ближайшего конфига, а не с чистого
листа: так параметры, которые не должны меняться, и не меняются.
